# Parity Matrix

Reference: https://github.com/microsoft/playwright-vscode. One row per upstream capability
named in the constitution. Status values: `full`, `partial`, `blocked`, `not-started`,
`zed-only`. Primitive values: `tasks`, `dap`, `lsp`, `settings`, `playwright-ui`, `none`.

| Capability | Status | Primitive | Note |
|------------|--------|-----------|------|
| Install Playwright | not-started | none | |
| Playwright project detection and selection | full | lsp | Detects every `playwright.config.*` with a resolvable `@playwright/test` (v1.38 gate, nearest config wins, monorepos). Test discovery waits for Zed's worktree trust on Zed 0.218+, otherwise for the per-workspace consent question (see the last row). Project (browser) picker as code actions, one `[x]`/`[ ]` entry per project plus "Select all projects" (feature 005): first project selected by default as upstream, single-project configs unchanged, runs pass `--project` per selected project, lenses follow the selection, the choice is remembered per config in the user's state directory (upstream: VS Code workspace state). `zed-only` addition: a folder default via `lsp.playwright.settings.projects`, forwarded by the shell's `language_server_workspace_configuration`. Zed limitation: the code action menu is cached per cursor position (`crates/editor/src/code_actions.rs`) and is not refetched after a command-only code action runs, so the check marks at an unchanged cursor lag one toggle behind; the server confirms every change in a notification instead (no API workaround, Zed issue to be filed by the owner). Files open before the extension starts are served without a reopen (Zed sends `didOpen` for every open buffer when a server starts, verified on Zed 1.24.2), except after an update or reinstall in the same session, when Zed keeps the extension's server stopped until `editor: restart language server` (Zed limitation, `crates/project/src/lsp_store.rs` `stopped_language_servers`, tracked as zed-industries/zed#60405). |
| Run tests with a single click | full | lsp | Run test, describe (`file:line` selects the whole group, verified), file and re-run via code actions and code lenses, executed by the workspace Playwright CLI. Results: progress, pass/fail notification, diagnostics at failing lines, full output in the language server log. Feature 006 closes the three former gaps with LSP surfaces Zed renders: the executing step and the per-step durations are inlay hints (`⌛ waiting…`, `<n>ms`, `<n>ms (ran <k>×)`; cleared on edit or next run; fed by a step reporter the server attaches to the run through Playwright's reporter API, as upstream does; `inlay_hints.enabled` must be on in Zed), and the run's full output is written to a log file in the user's state directory and opened as an editor buffer through `window/showDocument` from **Playwright: Show last run output** (upstream: Test Results panel). Differences from upstream, recorded: a trailing text label instead of a highlighted line, because Zed has no decoration API for extensions; a buffer instead of a panel. A real terminal remains the `zed-only` tasks recipe row below (extension LSP adapters cannot schedule Zed tasks; `crates/language_extension/src/extension_lsp_adapter.rs` has no `client_command`). Files open before the extension starts are served without a reopen (Zed sends `didOpen` for every open buffer when a server starts, verified on Zed 1.24.2), except after an update or reinstall in the same session, when Zed keeps the extension's server stopped until `editor: restart language server` (Zed limitation, `crates/project/src/lsp_store.rs` `stopped_language_servers`, tracked as zed-industries/zed#60405). |

| Discovery consent (Workspace Trust substitute) | partial | lsp | VS Code gates extension code execution with Workspace Trust. Zed 0.218+ has the equivalent, worktree trust (Restricted Mode): it starts language servers only in folders the user trusted and remembers that across restarts, so the server discovers at once in every reported workspace folder (feature 003). For older Zed, other clients and folders that reach the server only as the `rootUri` fallback, the server asks once per workspace per session before running `playwright test --list` (which executes the workspace's config and test files); until "Run discovery" is chosen, or "Playwright: Enable test discovery" is used, nothing runs and nothing is offered. |
